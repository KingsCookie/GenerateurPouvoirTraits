# Bug Report: Débordement horizontal de la section « Résilience » (Paramètres › Avancés) en mobile

**Type**: Implementation drift (coverage gap — sous-composant imbriqué non adapté au mobile)
**Severity**: Medium
**Feature**: 013-refonte-ui-mobile
**Reported**: 2026-07-30
**Status**: Patched
**Patched**: 2026-07-30

## Description

Sous 760 px, dans **Paramètres › Avancés**, la section « Résilience (global → type → trait) »
dépasse de l'écran : elle provoque un défilement horizontal et casse la mise en page « cartes à
lignes » attendue.

La cause est le composant enfant [`ResilienceOverrides.svelte`](../../../src/ui/components/ResilienceOverrides.svelte),
rendu par `ParametresView` mais **jamais adapté** lors de la Feature 013 :

- un `<table>` « Par type de trait » à 5 colonnes (Type + Initiale/Maximale/Seuil + « Propager »),
  avec des champs à largeur fixe (`td input { width: 4.5rem }`) et `.type-name { white-space: nowrap }`,
  dont la largeur cumulée dépasse un viewport ~360 px ;
- un sélecteur `.field.select select { min-width: 14rem }` (224 px) serré ;
- **aucun** bloc `@media (max-width: 760px)` dans le composant.

`ParametresView` a bien été passé en cartes à lignes en F013, mais la refonte ne s'est pas propagée
dans ce sous-composant (ni, à vérifier, dans les autres éditeurs imbriqués des « Avancés »).

## Artifact Traceability

### spec.md
- **User story affectée** : US5 — Paramètres en cartes à lignes (parcours Avancés).
- **Exigences affectées** : Paramètres « cartes à lignes » ; interdiction de débordement horizontal
  (individus/contenu en `flex`, pas de table scrollable).
- **Gap identifié** : la spec exige des cartes à lignes sans table à défilement horizontal, mais ne
  liste pas explicitement `ResilienceOverrides` (ni les autres sous-composants d'édition) comme
  fichiers à adapter — d'où l'oubli.

### plan.md
- **Sections affectées** : arborescence des fichiers à modifier (`src/ui/components/*`), qui
  n'inclut pas `ResilienceOverrides.svelte` (ni `Weightings`/pondérations si concernées).
- **Impact** : ajouter les sous-composants d'édition imbriqués dans les « Avancés » à la liste des
  fichiers portant un traitement `@media (max-width: 760px)`.

### tasks.md
- **Tâches affectées** : la tâche de refonte mobile de `ParametresView` (cartes à lignes) — sa portée
  s'arrête au conteneur et n'a pas couvert les composants enfants rendus dans les `fieldset` Avancés.
- **Fausses complétions** : la tâche « Paramètres mobile » est marquée faite alors que le rendu mobile
  des sous-composants (au moins `ResilienceOverrides`) n'est pas conforme.
- **Tâches manquantes** : ajouter une tâche « rendre `ResilienceOverrides` responsive < 760 px »
  (table → cartes/lignes empilées ou défilement contenu dans son propre conteneur `overflow-x`),
  et un audit des autres éditeurs imbriqués des Avancés.

## Contrats / invariants concernés

- **Section 5 (Paramètres)** : « `fieldset` en cartes à lignes (libellé gauche, champ droite ~96 px) ».
- **INV-M12** (principe transverse mobile) : « aucun `<table>` à défilement horizontal ; contenu en
  lignes `flex` ».
- **quickstart §15, §18, §55** : cartes à lignes ; aucune table à défilement horizontal.
- **INV-M1 / SC-004** : desktop ≥ 760 px doit rester strictement identique — le correctif doit être
  entièrement sous `@media (max-width: 760px)`.
- **INV-M2 / SC-005** : tokens seule source, aucune valeur en dur.

## Root Cause Analysis

Oubli d'implémentation (coverage gap). La refonte mobile des Paramètres a traité le conteneur
`ParametresView` mais pas ses sous-composants d'édition imbriqués. `ResilienceOverrides` conserve donc
une table et des largeurs fixes conçues pour le desktop, ce qui déborde sous 760 px. La spec/plan ne
nommant pas ces enfants explicitement, ils sont passés entre les mailles.

## Recommended Fix

1. `/speckit-bugfix-patch` — ajouter au plan/tasks la mise en responsive des éditeurs imbriqués des
   Avancés (au minimum `ResilienceOverrides`), en réaffirmant INV-M1/M2/M12.
2. `/speckit-bugfix-verify` — confirmer la cohérence spec ↔ plan ↔ tasks.
3. `/speckit-implement` — appliquer le correctif CSS/markup :
   - sous 760 px : transformer la table « Par type de trait » en lignes empilées (une carte par type,
     champs Initiale/Maximale/Seuil + « Propager »), **ou** confiner la table dans un conteneur
     `overflow-x: auto` afin que le corps de page ne défile jamais horizontalement ;
   - réduire/assouplir `min-width` du `select` (« Par trait ») et les largeurs d'input fixes ;
   - tout sous `@media (max-width: 760px)`, tokens uniquement, desktop inchangé.
